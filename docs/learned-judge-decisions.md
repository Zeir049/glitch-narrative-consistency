# 학습형 judge 계획 — 결정 배경과 검토 기록 (v2)

2026-11-06. [`learned-judge-plan.md`](learned-judge-plan.md)가 "무엇을 만들고 어떻게 검증하나"라면 이 문서는 "왜 그렇게 정했나"다.
초안은 Opus 세션이 썼고, 이 저장소의 판단 세션이 코드와 Weave 원본 저장소(`%USERPROFILE%\Downloads\event_sourcing`)를
대조해 두 차례 고쳤다. "측정"은 직접 잰 것, "기록"은 문서·주석에 적힌 것.

## 1. 방향: 에이전틱 대신 측정 기반 교체 (유지)

에이전틱 전면 도입은 하지 않는다. 규칙 checker는 그대로, LLM judge를 학습 모델로 바꾸되 측정으로 검증한다.
이유: 결과가 흔들린다(1회 판정은 정상 장면 10% 오탐, Weave Track 1), 지연·비용, 한 작품 맞춤의 전례(B-002).
주제는 "판정기 교체"가 아니라 **"LLM이 낀 파이프라인의 품질 속성을 요구로 정하고 결함 주입·녹화 재생·회귀 게이트·
비열등성 검정으로 검증한다"**이고, 판정기 교체는 그 사례다. 모델이 실패해도 검증 체계는 성과로 남는 순서로 만든다.

## 4. 판정기 선택 (유지)

`klue/roberta-base` 쌍 분류 cross-encoder, NLI 3클래스. 이유: CPU 결정적, 보정 쉬움, 근거 쌍 = 근거 사건 ID,
과거 사건 전량을 싣지 않아 프롬프트 폭증이 없다. 비교군(bge-reranker, 소형 LLM QLoRA)은 향후.
하지 않는 것: checker를 LLM으로(틀리는 방식이 달라야 한다), judge 출력으로 증류(순환), 구조형 모순으로만 학습(기여 0).

## 5. 학습 데이터 원칙 (유지 + 보강)

정답은 주입 과정에서 확정. 대조 묶음(같은 전제로 모순·정상·무관). 어려운 음성(회복 사건, 의수, 규칙 예외, 들은 장면, 장면 전환,
복선·점진·각성). LLM은 오프라인 생성기로만. 정답 오류율 표본 검수 200건. **학습 작품의 실제 장면도 섞는다**(주입 문장만으로는
문체 지름길). 작품 단위 분할 + 연산자 홀드아웃.

## 6. 장르 (유지, 데이터 갱신)

4코퍼스가 이미 장르를 가른다: WM(근미래 SF 웹소설), Q1(1987 가족극 = 장편소설 일반), Q3(폐쇄 공간 스릴러), 셜록(고전 추리 완역).
모든 지표를 작품별로 보고한다. 가설 H1~H4(장르 간 성능 차, 부정적 전이, 보정 차이, 지름길)는 그대로 향후 과제.

## 7. 작가 검수를 선택으로 만드는 논리

검수의 역할은 정확도가 아니라 오류 누적 차단. 대체 = 결정적 관문(exclude) + 신뢰 등급 표시 + 기존 재검수·철회 경로(수동).
빠진 것 = 사후 정정 자동화(철회 + 영향 회차 재검수), 승격, 자기 일관성. 이것이 "없이"라고 못 하는 이유다.

## 9. 소프트웨어공학 주장의 형태 (유지)

측정 가능한 요구 → 결정 기록(버린 대안 포함) → 검증 결과(결함 주입·비열등성·회귀) → 트레이드오프 표 → 재현 기록.
쓰지 않을 표현: "완벽한", "확실하게", 같은 정답·검정 없는 "LLM보다 낫다". "알려진 범위에서, 측정된 한계 안에서 동작한다".
