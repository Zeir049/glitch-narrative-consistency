## 0. 개정 (2026-11-06, 판단 세션 검토 후)

아래 세 가지가 조사 세션 원안을 덮어쓴다. 본문에서 충돌하는 문장은 이 절이 우선한다.

1. **KLUE-NLI 수치 정정.** 원안의 85.16 / 85.40 / 86.63은 KLUE README 표의 **STS F1** 열을 읽은 것이다. NLI ACC 열은
   small **79.33** / base **84.83** / large **89.17**이다. "small과 base가 0.24점 차"라는 모델 선택 근거는 성립하지 않는다(실제 5.5점 차).
2. **하드웨어 전제 변경.** 이 PC에 **RTX 3060 12GB**가 있다(서버·워커가 도는 PC). 학습은 Colab이 아니라 로컬, 추론은 워커 GPU가 기본이고
   CPU는 GPU 없는 배포 환경을 위한 대체 경로다. 따라서 "CPU 60초 안에 드는가"는 모델 선택의 1순위 기준이 아니다.
   모델 순서는 **base → large(상한 측정) → 정확도로 선택**, small·int8·버킷 패딩은 CPU 대체 경로에서만 쓴다.
   결정성(§2-5)은 GPU에서도 같은 기계·같은 드라이버·`torch.use_deterministic_algorithms(True)`·`CUBLAS_WORKSPACE_CONFIG=:4096:8`·
   배치 구성 고정으로 정의한다. large는 12GB에서 fp16·256토큰·배치 8(+gradient checkpointing)로 학습한다.
3. **데이터 순서 변경.** 선행 연구([`learned-judge-prior-work.md`](learned-judge-prior-work.md))에서 성공한 소형 판정기는 전부
   수천~수만 쌍 라벨을 썼다(MiniCheck 14K+21K, FactTrack 18.7K). 원안이 2단계로 미룬 LLM 생성 데이터를 **1단계**로 올린다:
   (A) FactTrack식 쌍 라벨링 1~2만 쌍, (B) FlawedFictions식 한국어 반사실 회차 200~300건(사람 검증). 구조 주입 `inject.py`는
   대조 묶음·어려운 음성 보조로 남긴다. 평가는 4코퍼스 실제 라벨만. 지표에 NoCha식 쌍 정확도와 근거 적중을 더한다.
   목표 수준은 recall 0.5 안팎·정상 장면 오탐 ≤ 0.05 — **내부 목표**다. 발표 주장은 R2(동결 열 대비 비열등)이고, ConStory 0.55/0.88·
   FactTrack 0.60/0.60은 지표 단위가 달라 "문헌 수준"의 근거가 아니다.
4. **검증 기록 반영**([`learned-judge-design-review.md`](learned-judge-design-review.md)). (a) GPU 추론 정밀도는 **fp16**(모델 메타에 고정 기록),
   fp32는 CPU 대체 경로. 3060에서 large·256토큰·회차 3,550쌍은 fp16 약 25~40초, fp32 약 50~90초 [추정]; 할당량 24면 약 2,660쌍이라 그 3/4.
   (b) GPU 결정성 조건에 같은 torch·CUDA 툴킷·cuDNN 판, `cudnn.benchmark=False`, SDPA 백엔드 고정을 더하고, 배치 모양 불변성은 보장되지
   않으므로 배치 구성을 입력에서 결정적으로 정한다. (c) **누수 규칙**: LLM 쌍 라벨링·반사실 회차는 각 접기의 학습 작품 확정 회차에서만,
   평가 작품의 회차·장면은 라벨링·생성에 쓰지 않는다. 반사실 산출물은 학습 전용. (d) 쌍 정확도는 학습·검증 진단 지표(4코퍼스에 대조 쌍
   필드 없음), 근거 적중은 WM에만 가능(Q1·Q3·셜록 지도는 사람 확정 전). (e) §2-0 근거 포함률(53/75 → 73/75)은 지도의 matched·ambiguous
   후보 전부로 센 값이다(matched만이면 48/69 → 67/69, 비율 같음). (f) 갈래 A의 참 양성은 드물고(원작 원장은 거의 일관) 갈래 B가 양성의
   주 공급원이다. 이중 라벨 불일치 제외율을 보고하고, 음성도 재작성본을 둔다.
5. **데이터 생성 LLM은 로컬·무료만 (사용자 결정 2026-11-07).** ⚠ **§0-7(a)에서 정정 — 이 규칙은 API 호출 기준이다. Claude Code 세션이 직접 쓰는 데이터는 허용.** 유료 API 키는 **검증 단계(LLM 기준선 재측정, 평가셋 소량)에만** 쓴다.
   학습 데이터(§0-3 갈래 A·B)의 생성기는 이 PC의 RTX 3060에서 도는 로컬 모델이다 — OpenAI 호환 서버(llama.cpp 서버 또는 Ollama, 127.0.0.1에만 바인딩)를
   띄우고 `WEAVE_LLM_PROVIDER=openrouter` + `OPENROUTER_BASE_URL=http://127.0.0.1:<port>/v1` + 더미 키로 어댑터 경로를 그대로 쓴다(코어
   `weave_llm.py`가 환경변수 `OPENROUTER_BASE_URL`을 읽으므로 코어 수정 없음). 무료 OpenRouter 키(하루 50회)는 보조. 로컬 생성물은 품질이 낮으므로
   자기일관성 필터와 사람 검토를 그대로 두고, 갈래 A 쌍 라벨링은 로컬 모델 2개(계열이 다른 것) 이중 라벨로 한다.
   중간 단계로 사람 검증 영어 모순 쌍 약 940개(FlawedFictions 817 + ContraDoc story 125, MIT·Apache-2.0;
   [`related-work-extraction-verification.md`](related-work-extraction-verification.md) §5)를 문장 단위로 로컬 번역해 KLUE-NLI와 Weave 데이터 사이에 둘 수 있다.
   **첫 실험은 외부 데이터 없이**(KLUE-NLI → 구조 주입 + 실제 장면) 돌리고, 학습 곡선이 데이터 부족을 가리킬 때 로컬 생성·번역 데이터를 더한다.
   FABLES 인용문은 저작권 책 발췌라 재배포하지 않는다.
   **시험 결과(세션 H, 2026-11-07, `docs/local-llm.md`):** 로컬 경로 자체는 코어·어댑터 무변경으로 동작한다(llama.cpp b12177, 127.0.0.1:8080,
   출력 50~63 tok/s, VRAM 7.2 GB). 그러나 **A.X-4.0-Light 7B는 학습 데이터를 못 만든다** — 쌍 라벨 이중 일치 κ 0.005(우연 수준, 제외율 72%),
   반사실 회차 0/3 통과(사실을 깨지 않고 되풀이, 대조 장면을 위반 장면으로 복사). 판단: 이 결과는 "첫 실험은 외부 데이터 없이"라는 순서를
   확인해 준다. 로컬 생성(갈래 A·B)은 2단계로 두고, 2단계에 들어갈 때 (a) 12 GB에 드는 더 큰 모델(Qwen2.5-14B-Instruct Q4_K_M ≈ 9 GB 등)과
   (b) H가 제안한 프롬프트 분할(계획→장면, 대조 장면 별도 호출, 라벨 2단계)을 **같은 50쌍·3건 시험으로 먼저** 재평가한다.
   영어 쌍 번역(문장 단위)은 라벨링보다 쉬운 과제라 7B로도 가능할 수 있으며, 학습 곡선이 부족을 가리킬 때 먼저 시도할 2단계 후보다.

6. **J(첫 실제 학습) 착수 판단 (2026-11-07, 설명 세션 점검 `explainer-J-readiness-review.md` 반영).** 선택지 "나": J 세션은 학습 전에
   측정의 유효성에 걸리는 빈 곳을 먼저 메우고 관문 G0~G3을 통과한 뒤 1접기만 학습한다. 뒤로 미루는 것(새 연산자 4개·템플릿 ≥12, `judge_eval --model-dirs`,
   장면 시간 p50/p95)은 1접기 결과를 본 뒤 2차 세션에서 한다.
   - **정밀도 통일(결정)**: 학습 검증 logits(온도·기준값·조기 종료의 입력)와 서비스 추론은 **같은 정밀도·같은 어텐션 구현**으로 계산한다.
     GPU 기본 fp16 — autocast가 아니라 `model.half()`로 고정 — CPU 대체 경로는 fp32. 어텐션은 `attn_implementation="eager"`로 고정(SDPA 백엔드
     선택의 비결정성을 피하는 가장 단순한 방법, 속도 손실은 감수). `judge_meta.json`에 `precision`·`attn_implementation`을 기록하고 `HFBackend`가
     그 값을 읽어 같은 조건으로 로드한다(지금은 fp32 고정·meta 미참조 — 고친다). 학습 순전파는 AMP를 써도 되지만 검증·기준값 산출은 위 조건.
   - **G3 경로**: KLUE-NLI 기초 학습 모델을 지우지 않고 `judge_meta.json`(threshold 0.5, pairs_version, precision)과 함께 보존해 하네스로
     "영 학습 기준선"을 낸다. 기초 모델은 접기 간 공유한다.
   - **G1 도구** `scripts/eval/judge_latency.py`: 합성 회차(사건 30·과거 사건 300)에서 base·large fp16(GPU)과 small/base fp32(CPU) 회차 시간.
     가중치는 기초 모델로 충분(시간은 가중치와 무관).
   - **주입 누수 규칙 보강(§2-6)**: 접기의 주입 데이터는 **학습 작품의 레지스트리·원장만** 기반으로 만든다. 평가 작품의 인물 이름·규칙이 들어간
     주입(예: WM 평가 접기에서 WM 레지스트리 기반 주입)은 누수로 본다. `inject.py` CLI가 `entity_registry.json` 파일명만 열어 Q1·Q3·셜록
     레지스트리를 못 쓰는 것을 고친다(`registry_live.json` 허용).
   - **첫 접기**: 평가 작품 **Q3**(train = WM + 셜록, val = Q1). §2-6 순환(q3→검증 q1)과 같다. 평가 작품 Q3는 G6을 넘기 전에는 돌리지 않는다.
   - **환경**: 앱 `.venv`와 분리한 `.venv-train`(CUDA torch는 PyTorch 공식 CUDA 인덱스로, `pip install -e .[train]`은 Windows PyPI에서 CPU torch를
     받으므로 쓰지 않는다). 설치·모델·데이터 다운로드(CUDA torch, `klue/roberta-base`·`-large`, KLUE-NLI)는 J 세션이 사용자 승인을 받는다.
     `load_dataset("klue", "nli")`가 현 datasets 판에서 되는지 먼저 확인. 학습 중 llama-server는 내려 둔다(GPU 공유 금지).
   - **전제**: I(WM timeline 수정, `392777d`)를 먼저 main에 합친 뒤 분기한다.
   - **G0 토큰 길이 결정(2026-11-07, J 측정 뒤)**: 실제 토크나이저로 잰 쌍 토큰 p95는 WM 222 / Q1 348 / 셜록 320(Q3 394, 평가 작품이라 참고)로
     256을 넘는다. 긴 쪽은 가설(머리 + 사건 요약 + 발췌 160자, p95 190~210). 발췌를 64자로 줄이면 256에 들지만 수치 보존 결정(B-027)을 되돌리는 것이라
     택하지 않는다. **GPU 경로 `max_length`를 384로 올린다**(설정 기본값 256→384, meta 기록). 근거: J 측정 GPU 지연 base 6.3 s/30사건(256),
     Q1 5,830쌍 base fp16 19.3 s(256)→24.4 s(384) — 상한 60 s에 여유. CPU 대체 경로는 256에서도 small 116 s·base 233 s로 상한을 넘으므로
     "대체 경로 미달"로 기록하고 int8·할당량 축소는 후속. 쌍 텍스트는 바뀌지 않으므로 내보낸 학습 데이터는 그대로 쓴다.

7. **K·D1·E·E4 결과와 실험 L 사전 확정 (2026-11-07 밤, 판단 세션 · 사용자 승인).** 결과 상세는 K 브랜치

     로컬 실패(§0-5 시험 결과) 뒤 미뤄졌고, **J·K·D1·E·E4의 학습 데이터에 LLM 생성물은 0이다**(라벨 v2는 규칙, 주입은 템플릿, FF+CD 번역만 로컬 A.X).
     단 학습 데이터와 평가 라벨을 같은 판정자에게서 내지 않는다. **⚠ 정정(2026-11-08):** 앞서 "평가 라벨(셜록·Q3 심은 모순)은 Claude 생성물이 아니다"라고
     적었으나 틀렸다. Q1·Q3·셜록 평가 장면 45개 중 40개, 모순 장면 20개 중 17개는 `llm:claude-opus-5` 집필이다(`tests/eval/weave_judge_corpus/*/README.md`
     authored_by). 셜록은 원작 5편(원장)만 사람 저작이다. 실험 L의 학습 데이터(Claude Sonnet 5.5)와 같은 계열이므로, 치우침이 있다면 L에 **유리한** 쪽이다.
     사람이 심은 모순으로만 된 평가셋은 M-3(타이타닉)이 처음이다.
   - **(b) 지금까지 [측정, 모두 장면 AUROC, '제외' 포함 max, 층화 bootstrap 95%].** 라벨 v1 결함(`premise_id ∈ 근거`만으로 모순) → v2 수정,
     감사 정밀도 WM 0.97 · 셜록 0.84 · Q1 0.43. Q1: r1 0.562 [0.394, 0.728] · r2 0.528 — 관문 미달. D1(WM→셜록) 0.522 — 전이 없음.
     E(셜록): E1(KorNLI fiction) 0.644 [0.478, 0.798] · E2 0.448 · E3 0.564. E4(large) 0.650 [0.484, 0.802]. **모두 "없음", Q3 봉인.**

       전제 문장은 스크립트가 premise_id로 원장에서 복사. 목표 모순 ~300 · 일관 ~300. L2 = **외부 정리** — FF+CD 모순을 원문 맥락에서 혼자 읽히는

     - **항목:** 작품 하나에서 앞부분(앞선 원문)과 대상 구간(문단 1–3개, 최대 약 1,500자)을 고른다.
       - P(모순판): 대상 구간에 앞부분 사실과 충돌하는 수정을 하나 넣는다.
       - N(정상판): 같은 자리에 비슷한 크기의 일관 수정을 넣는다. 고친 흔적 지름길을 막기 위해서다.
       - P/N은 쌍둥이다.
     - **목표:** 60쌍(P 60 + N 60), 작품 10편 이상, 작품당 최대 8쌍이다. 유형(상태·설정·지식·시간)을 고르게 섞는다.

       - **둘 다 맞혀야 채택**한다(P는 둘 다 모순이고 근거가 심은 사실, N은 둘 다 무모순). 탈락률을 보고한다.
       - 사용자 표본 확인 10쌍은 선택이다.

## 1. 결론 요약

1. **모델** (§0에서 개정): `klue/roberta-base`를 먼저 학습하고 `-large`로 상한을 잰 뒤 정확도로 고른다(KLUE-NLI ACC small 79.33 / base 84.83 / large 89.17 [기록]). small은 GPU 없는 배포 환경의 대체 경로. reranker·소형 LLM은 버린다.
2. **지연**: GPU(기본) large fp16·256토큰·할당량 24면 회차(30사건, 약 2,660쌍)당 약 20~30초, fp32면 40~70초 [추정, §0-4]. CPU 대체 경로는 지금 설정(base, `padding="max_length"` 512, 전제 상한 32)으로 6~30분 [추정]이라 small·256 버킷·전제 축소가 함께 필요하다. 첫 실험의 첫 관문은 워커 GPU 실측이다.
3. **쌍 정식화 변경 있음**: 상한 32와 kind 순서 때문에 정답 근거 전제가 쌍에 아예 들어가지 않는 장면이 많다. 근거가 들어간 양성 장면은 상한 32에서 53/75, 상한 없음에서 73/75다 [측정]. 셜록은 7/16, Q3는 규칙 38개가 상한을 다 채운다. 바꿀 것은 kind별 할당량, kind 안 관련도 정렬, 발췌 160자 자르기, 회차 간격·사이 사건 표기다.
4. **학습 레시피**: KLUE-NLI 기초 학습(1~2 에폭) → 본 학습. 손실은 클래스 가중 CE(빈도의 −½승), 묶음 단위 샘플링으로 모순:정상:무관 ≈ 1:1:2를 맞추고, 근거가 불확실한 쌍은 '제외'로 둔다. 시드 3개를 돌려 검증으로 고른다. focal loss는 쓰지 않는다.
5. **양성 확보**: 학습 작품을 WM 하나에서 다른 작품 3개(교차 적합)로 넓혀 실제 양성을 늘린다. 주입 기반 작품도 넷으로 넓히고 어려운 음성 연산자 4개를 더한다. LLM 라벨·반사실 데이터는 1단계이고(§0-3, 누수 규칙 §0-4c), 가설만 보는 기준선으로 지름길을 감시한다. 필요한 양성 수의 하한은 문헌에서 이 설정에 맞는 수치를 찾지 못했다. 학습 곡선(25·50·100%)으로 잰다.
6. **집계·보정**: 집계는 최댓값 그대로 둔다(SummaC-ZS와 같은 계열). 온도 보정은 쌍 단위로 하고, **기준값은 장면 단위**(쌍 확률 최댓값)로 고른다. 기준은 "검증 작품 정상 장면 오탐 ≤ 0.05에서 recall 최대"이고 F1 최대는 쓰지 않는다. ECE는 작품별로 구간과 함께 보고한다.
7. **평가 분할**: 작품 하나 빼기 교차 적합. 평가 작품을 뺀 셋 중 하나가 검증이다. WM·Q1·Q3 예측 60개를 모아 동결 열과 대응 bootstrap을 하고, 셜록은 따로 보고한다.
8. **검정력**: 양성 60에서 learned recall이 동결 열과 같고 엇갈리는 장면이 12건이면 하한이 −0.10에 걸린다 [측정, 모의]. 하한 > −0.10이 나오려면 대략 recall이 +0.05 이상이고 엇갈림이 15건 이하여야 한다. 못 넘으면 구간을 그대로 주 결과로 쓴다.
9. **결정성**: 같은 기계·같은 스레드 수·같은 라이브러리 판이면 비트 동일을 기대할 수 있다. 다만 보장 문서는 찾지 못해 테스트로 확인한다. 고정할 것은 GPU: torch·CUDA·cuDNN 판, `use_deterministic_algorithms(True)`, `cudnn.benchmark=False`, SDPA 백엔드, `CUBLAS_WORKSPACE_CONFIG`, 정밀도(fp16, 메타 기록), 입력에서 결정되는 배치 구성 / CPU 대체 경로: 스레드 수, MKL_CBWR, fp32, 버킷 패딩. 판 고정과 해시 기록은 공통. 배치 모양 불변성은 보장되지 않는다.
10. **실행 비용**: 로컬 3060에서 base·large × 4 접기 × 시드 3 = 24회(large는 fp16·256·배치 8, 체크포인팅 선택), 대략 6~12시간 [추정]. 산출물은 접기별 모델 폴더, `judge_meta.json`(pairs_version·온도·장면 기준값·지표·판), `.sha256` 이다.

|---|---|---|---|---|
| base · 512 고정 패딩 (지금 코드) | ≈500 ms | ≈170 ms | ≈4 s | ≈350 |
| small · 512 고정 | ≈250 ms | ≈85 ms | ≈2 s | ≈700 |
| small · 256 버킷 | ≈110 ms | ≈37 ms | ≈0.9 s | ≈1,600 |
| small · 256 버킷 · int8 | ≈55 ms | ≈18 ms | ≈0.45 s | ≈3,300 |

**회차당 쌍 수**: [측정] 사건당 가설 수는 WM 1.8 / Q1 3.7 / Q3 4.3 / 셜록 3.7이고, 상한 32는 거의 항상 찬다(Q1 211쌍/6.6가설 = 32).

- 지시문의 추정: 장면 6 × 가설 5 × 32 ≈ **1,000쌍**.
- 계획서 기준(사건 30개): 30 × 3.7 × 32 ≈ **3,550쌍**.

지금 코드로 1,000쌍이면 170~500초, 3,550쌍이면 600~1,800초다. **60초를 넘는다.**
small·256 버킷과 전제 할당량 합 16을 쓰면 30 × 3.7 × 16 ≈ 1,780쌍이고, fp32에서 약 66초, int8에서 약 32초다. 경계에 있으므로 실측으로 정한다.

**버린 대안.** large: 버리지 않는다 — NLI +4.3점, 연산 3.5배, GPU 추론이면 서비스 후보(§0). CPU 경로에서만 제외. reranker: 관련도 단일 점수라 '관련되지만 일치'와 '모순'을 나누려면 결국 같은 3클래스 재학습이 필요하고, 0.6B라 CPU 비용이 크다. 소형 LLM: 쌍당 1~3B × 2 × 300토큰 ≈ 0.6~1.8 TFLOP으로 회차당 수 시간이 걸린다.

**불확실한 점.** 워커 CPU의 실제 코어·명령어 집합(AVX-512/VNNI 여부)을 모른다. 위 표는 Ice Lake 2코어 측정 하나에서 늘인 값이다. 한국어 KLUE 토크나이저의 글자당 토큰 수도 재지 못했다(transformers 미설치). 1토큰 ≈ 1.5~2.5자로 가정하면 Q1 쌍 p90 1,143자는 460~760토큰이다.

### 2-2. 적은 양성으로 배우는 법

**결정.**

1. **KLUE-NLI 기초 학습은 한다**(1~2 에폭, max_length 128). 매핑은 entailment→정상, contradiction→모순, neutral→무관 그대로 두되, 아래 불확실성을 기록한다. 기초 학습만 한 모델의 검증 작품 장면 성능을 "영 학습 기준선"으로 함께 보고한다. 비용은 3060에서 수 분이다.
2. **불균형 처리**: 클래스 가중 CE(가중치 ∝ 빈도^−½, 평균 1로 정규화) + **묶음 단위 샘플링**. 대조 묶음·실제 장면 단위로 뽑고, 무관 쌍은 에폭마다 모순+정상의 2배까지 무작위로 줄인다(시드 고정). 기준값은 따로 고르므로 가중치는 학습 신호의 균형만 맡는다. focal loss는 쓰지 않는다. 보정을 나중에 온도로 다시 맞춰야 하고, 이 설정에서 가중 CE보다 낫다는 대조 근거를 찾지 못했다.
3. **'제외' 라벨 도입**: 실제 모순 장면에서 근거 전제가 아닌데 근거와 같은 (엔티티, 필드)이거나 같은 사건을 가리키는 쌍은 '무관'이 아니라 손실에서 뺀다. 설정 유형 모순 장면의 규칙 전제(지도에 규칙 ID가 없다)도 뺀다. "명시 안 됨 = 무관" 근사의 잡음이 가장 큰 곳이다.
4. **대조 묶음 유지·확대**: 같은 setup에서 모순/정상/무관을 함께 내는 지금 구조를 유지한다. 어려운 음성 연산자 4개를 더한다(§3-1 `inject.py`).
5. **양성 늘리기**: 실제 장면은 학습 작품 3개에서 가져온다(교차 적합). 접기마다 실제 모순 장면 40~60개 × 근거 쌍 1~3개 ≈ 80~150 실제 양성 쌍이고, 지금 WM 하나의 98보다 많다 [추정]. 주입 기반 작품을 WM에서 학습 작품 3개로 넓혀 이름·문체 다양성을 얻는다.
6. **LLM 라벨·반사실 데이터는 1단계다**(§0-3). 라벨 잡음·지름길 위험(아래 근거)이 있으므로, LLM 데이터 없는 조건(구조 주입 + 실제 장면)을 대조 조건으로 같은 검증 절차에서 함께 학습해 득실을 재고, 가설만 보는 기준선(G4)을 통과 관문으로 둔다.

**근거.**

- 전이. KLUE-NLI는 문장 대 문장 과제라 우리 쌍(구조 필드 + 발췌 + 요약)과 입력 단위가 다르다. SummaC는 NLI의 문장 단위 학습과 문서 단위 판정의 **입도 불일치**가 기존 NLI 기반 불일치 검출이 약했던 주원인이라고 보았다. MNLI만 학습한 모델은 문서 전체를 전제로 줄 때 56.4%, 문장 단위로 쪼개면 73.5%였다. 그러니 전이는 "짧고 명시적인 부정·반의 관계"에서 기대할 수 있고, "다쳤다 → 펜을 쥔다" 같은 세계 지식 추론에서는 약하다고 본다 [추정].
- DECODE(대화 모순)는 기존 NLI 데이터보다 **과제 내 데이터**가 감독 신호로 훨씬 효과적이었다. 발화를 짝지어 넣는 구조형 방식이 평평한 연결보다 분포 이동에 강했다. 우리 쌍 정식화가 구조형에 해당한다.
- neutral→무관 매핑의 문제. KLUE neutral은 주제가 같은데 판단할 수 없는 가설이고, 우리 '무관'은 대부분 주제가 다르다. 판정에는 모순 확률만 쓰므로 영향은 제한적이다. 그래도 '정상'과 '무관'의 경계는 흐려진다 [추정].
- 소수 표본 미세조정은 불안정하다. Zhang 외(ICLR 2021)는 원인으로 편향 보정 없는 옵티마이저, 상위층 초기값, **너무 짧은 학습**을 들었다. HF `AdamW`는 편향 보정을 한다. 에폭을 더 길게(5~10, 검증으로 조기 종료) 잡고 시드를 여러 개 돌린다.
- 대조·반사실 데이터. 최소 편집으로 라벨을 뒤집는 데이터(Kaushik 외 2020)는 가설만 보는 편향을 줄인다고 보고됐다. 반면 Huang·Liu·Bowman(2020)은 SNLI에서 일반화 이득이 없었다고 보고했다. 효과는 섞여 있고, 우리에게는 "같은 전제에 모순·정상이 함께 있어 전제를 봐야만 풀린다"는 지름길 차단 효과가 주 목적이다.
- LLM 증강의 위험. LLM이 만든 NLI 데이터에서 BERT 계열 **가설만 보는** 분류기가 86~96% 정확도를 냈다(Proebsting & Poliak 2024). WANLI는 사람이 고치고 라벨을 다는 과정을 거쳐 이득을 얻었다(HANS +11%, ANLI +9%, MNLI 4배 크기 대비). 걸러지지 않은 생성물은 지름길의 원천이다. 이 경고는 §0-3의 LLM 라벨·반사실 데이터에도 그대로 해당한다 — 그래서 이중 라벨 불일치 제외율을 보고하고 G4를 관문으로 둔다.

**필요한 양성 수.** 이 설정(한국어, 구조+자유 서술 쌍, 작품 간 일반화)에 해당하는 문헌 수치는 찾지 못했다. **모른다.**
대신 학습 곡선으로 잰다. 접기마다 학습 양성을 25/50/100%로 줄여 검증 작품 장면 recall을 그린다.
100%에서도 기울기가 가파르면 양성이 부족하다는 신호이므로 갈래 B(반사실)를 늘린다.

**버린 대안.** focal loss(위). 단순 복제 오버샘플링: 같은 쌍을 반복해 외우게 되므로, 묶음 단위 샘플링으로 대신한다. 무관 쌍 전량 학습: 4% 양성에서 손실의 대부분이 쉬운 무관에 쓰인다.

**불확실한 점.** '제외' 규칙이 실제 정답을 버리는 비율. 지도 후보가 문자열 대조라 표본 검수(결정 기록 5장, 200건)가 필요하다. 다른 작품 주입이 WM 템플릿 소재(상태 8·규칙 4·비밀 4)를 공유하는 한 문체 지름길은 남는다.

### 2-3. 쌍 정식화

**결정.**

| 항목 | 결정 |
|---|---|
| 클래스 | 3클래스 유지(KLUE-NLI 머리 전이 + '관련'과 '무관'을 나누면 할당량 정렬에도 쓸 수 있음). 판정은 p(모순)만 |
| 집계 | 최댓값 유지. 보고에 상위 2쌍과 그 전제 kind를 남긴다 |
| 전제 선택 | **kind 순서 + 상한 32를 kind별 할당량 + kind 안 관련도 정렬로 바꾼다** (아래) |
| 사건 단위 가설 | 유지(규칙 위반용). 그 가설의 ledger 전제는 사건 엔티티 전부가 아니라 관련도 상위만 |
| 발췌 길이 | 가설 원문·전제 발췌를 각각 앞 160자로 자른다. 쌍 전체 토큰 p95 목표는 GPU 경로 **≤ 384**(§0-6 G0 결정; 256은 CPU 대체 경로 목표) |
| 시간 관계 | 가설에 현재 회차, 전제에 `since N화 · 경과 M−N화`, ledger 전제에 since 이후 같은 엔티티·필드의 사건 요약 1줄을 붙인다 |

**전제 선택 개정안** (가설당 합 24, 지연이 허락하면 32; 할당량은 사전 고정한다).
남는 칸은 다음 kind로 넘긴다.

| kind | 할당 | kind 안 정렬 |
|---|---|---|
| checker | 전부(보통 0~2) | ID |
| ledger | 6 | 같은 (엔티티, 필드) 먼저, 다음 관련도 |
| knowledge | 6 | 관련도 → 최근 순 |
| rule | 4 | 관련도(가설과 문자 2-gram Dice) → ID |
| past | 6 | 관련도 → 최근 순 |
| scene | 2 | 관련도 |

관련도는 결정적 계산으로 둔다. 가설 머리(엔티티·필드·값·근거)와 전제 본문의 문자 2-gram Dice이고, 동률은 지금 키(ID·최근 순)로 깬다.
LLM·임베딩은 쓰지 않는다. 할당량은 위 순위 측정(정답 근거는 ledger·knowledge가 대부분이고, past가 그다음)에서 정했다.
**이 측정은 평가 작품 라벨을 썼다**. 그래서 할당량은 지금 한 번만 정하고, 결과를 본 뒤 바꾸지 않는다.

**근거.**

- 상한·순서가 recall을 깎는다: §2-0 표(53/75 대 73/75, 셜록 7/16). 원인은 두 가지다. (1) 규칙이 knowledge보다 앞서 전부 실린다(Q3 38개). (2) knowledge가 많은 인물은 최근 순 상위만 남는다(셜록 인물당 최대 154).
- 최댓값 집계: SummaC-ZS가 문서 문장별 최댓값(근거 하나면 충분)을 쓴다. 모순 검출도 근거 전제 하나면 성립한다. noisy-OR(1−∏(1−pᵢ))은 쌍 수에 따라 점수가 부풀어서, 장면당 쌍 수가 64~544로 8배 차이 나는 우리 데이터에서 장면 간 기준값이 비교되지 않는다. 학습된 집계기(SummaC-Conv: 히스토그램 + 1D conv, ZS 72.1 → 74.4)는 장면 라벨이 필요한데, 접기마다 학습 장면이 120개 남짓이라 과적합 위험이 이득보다 크다고 본다 [추정]. 향후 과제로 둔다.
- 시간 관계: 원장 재생이 "최신 상태"를 이미 만든다. 회복 사건이 **추출되어 있으면** ledger 전제가 회복 값을 since와 함께 보여 주므로 쌍 분류로 다룰 수 있다. 추출되지 않았으면 판정기는 못 본다. 쌍 하나는 전제 둘 사이의 순서를 모르므로 "경과 회차"와 "since 이후 사건 1줄"을 전제 안에 넣어 준다. 지금 가설에는 현재 회차가 없다(`_hypotheses`가 `episode`를 쓰지 않는다). transient·decays_to 표기는 이미 있다.
- 발췌 길이: Q1 쌍 글자 수 p90 1,143, p99 1,962 [측정]. 512토큰을 넘는 쌍이 상당수이고, `truncation=True`(longest_first)는 긴 쪽 끝을 자른다. 그러면 원문 발췌의 핵심 수치가 잘릴 수 있다. Weave 개선 1차(B-027)가 원문 160자 발췌로 수치 증발을 막았다 [기록]. 160자 자르기는 그 길이를 따른 것이다. 256토큰 목표는 지연(§2-1)과 같은 결정이다.

**버린 대안.** 이진(모순/아님) + 관련도 별도 모델: 모델이 둘이면 CPU 비용이 두 배다. 3클래스 머리 하나로 관련도도 얻는다. 상한만 올리기(64·128): 셜록이 128에서도 9/16이고 쌍 수가 2~4배 늘어 지연이 넘친다.

**불확실한 점.** 관련도(2-gram Dice)가 정답 근거를 앞으로 올리는지는 구현 뒤 같은 측정(`pair_coverage.py`)으로 확인해야 한다. 목표는 할당량 합 24에서 근거 포함 66/75(상한 128 수준) 이상이다. 못 미치면 할당량이 아니라 관련도 함수를 고친다. 이때도 학습 작품에서만 고친다.

### 2-4. 보정과 기준값

**결정.**

1. 온도 보정은 지금처럼 **쌍 단위**로 한다. 검증 작품 쌍 logits에 단일 T(NLL 최소)를 쓰되, '제외' 쌍은 뺀다.
2. **기준값은 장면 단위로 고친다.** 검증 작품의 장면마다 p_scene = max p(모순)을 계산한다. "정상 장면 오탐율 ≤ 0.05(Q 작품은 25장면 중 1건)에서 recall 최대, 동률은 높은 기준값"으로 정하고, 이 규칙을 사전 고정한다. 쌍 단위 F1 최대(지금 `pick_threshold`)는 버린다.
3. 보고: 작품별 쌍 단위 ECE(동일 개수 10구간, bootstrap 95% 구간)와 신뢰도 그림, 장면 단위 Brier, 장면 p_scene 분포(양성/정상)를 낸다. 작품 간 비교는 "검증 작품에서 고른 기준값이 평가 작품에서 낸 오탐율"로 한다. 이것이 실제로 문제가 되는 보정 차이다.
4. 애매한 구간: 제품 표시용으로 [기준값 − 0.1, 기준값) 장면에 "낮은 확신 — 학습 판정 경계"를 붙인다. **R2 집계에는 쓰지 않는다**(양성은 기준값 이상만). 폭 0.1은 근거 없는 사전값이다. 첫 실험에서 검증 작품 p_scene 분포를 보고 다음 판에서 정한다.

**근거.**

- 판정은 장면당 64~544쌍의 최댓값이다. 쌍 단위 F1로 고른 기준값은 최댓값 분포(쌍 수가 많을수록 위로 밀린다)와 맞지 않아 장면 오탐이 체계적으로 커진다 [추정]. 하네스가 재는 것은 장면 단위다.
- 동결 열 오탐 0.05 [기록]가 R2의 짝이다. recall만 비교하는 R2에서 오탐을 따로 묶어 두지 않으면 기준값을 내려 recall을 사는 일이 생긴다.
- 온도 보정은 사전학습 트랜스포머의 분포 안 보정에 효과적이다. 분포 밖(다른 작품)에서는 효과가 줄고, 라벨 스무딩이 분포 밖에 더 낫다고 보고됐다(Desai & Durrett 2020). 우리 검증·평가는 서로 다른 작품이라 분포 밖에 해당한다. 그래서 라벨 스무딩 0.1을 본 학습 선택지로 넣고, 두 조건(없음/0.1)을 검증 작품 ECE로 고른다.
- 장면 45개로 ECE를 내면 구간당 4~5장면이라 숫자가 흔들린다. 그래서 쌍 단위 ECE + 구간을 낸다.

**버린 대안.** 작품별 기준값: 서비스에서는 새 작품의 라벨이 없다. `--target-precision`: 유병률이 작품마다 달라(정상 10~25) 정밀도 목표가 작품 간에 비교되지 않는다.

**불확실한 점.** 검증 작품 정상 25장면에서 오탐 ≤ 1건이라는 기준은 기준값 추정을 거칠게 만든다(1건 차이 = 0.04). 기준값 안정성을 검증 장면 bootstrap 분산으로 함께 보고한다.

**결정.** R3("같은 입력 두 번 → 결과 완전 일치")는 **같은 기계·같은 설정** 범위로 정의하고, 아래를 고정한다. 기계 간 일치는 목표로 삼지 않고 결과 JSON에 환경을 기록한다.

**근거.** 부동소수 덧셈은 결합법칙이 성립하지 않아 연산 순서가 바뀌면 결과가 바뀐다. MKL CNR은 같은 명령어 집합 분기와 **고정 스레드 수**에서 같은 결과를 약속한다(Intel 문서). 다른 프레임워크 사례지만, CBWR을 켜도 GEMM 입력 모양(행 수)이 바뀌면 소수 넷째 자리가 달라졌다는 보고가 있다. 즉 배치 크기 불변성은 보장되지 않는다. LLM 추론 비결정성의 주원인이 배치 불변성 부재라는 분석(Thinking Machines, 2025-09)도 같은 방향이다.

우리 판정은 입력이 같으면 배치 구성도 같으므로 R3는 영향을 받지 않는다. "같은 쌍이 다른 장면 안에서 다른 확률"은 1e-6 수준으로 남을 수 있다. 기준값 근처 뒤집힘이 실제로 문제가 되면 배치 1(버킷 패딩)로 바꾼다. 이때 처리량 손실은 CPU에서 작다 [추정]. GPU도 같은 논리다.

PyTorch CPU가 고정 스레드에서 실행 간 비트 동일하다는 **공식 보장 문서는 찾지 못했다**. 포럼 답변 수준의 근거(스레드 1이면 같아진다)만 있다. 그래서 테스트로 확인한다(아래). GPU는 cuBLAS 문서가 같은 툴킷 판·같은 아키텍처·같은 SM 수에서 실행 간 비트 동일을 설계 보장으로 적고, PyTorch 문서는 판·플랫폼 간 재현을 보장하지 않는다(검증 기록 §3-3).

**확인 테스트.** 모델이 생기면 다음을 확인한다.

1. 같은 프로세스에서 두 번 돌려 확률 배열이 비트 동일한지 본다(`tobytes()` 비교).
2. 프로세스를 다시 띄워 같은지 본다.
3. 스레드 1과 N을 비교해 차이가 얼마인지 기록하고, 기준값 ± 1e-4 안의 쌍 수를 센다.
4. 결과 JSON에 `torch.__version__`, `torch.backends.mkldnn.is_available()`, CPU 모델명, 스레드 수, MKL_CBWR를 남긴다.

**불확실한 점.** 워커가 AMD CPU면 MKL은 COMPATIBLE 경로로 돌고, 성능이 떨어질 수 있다. oneDNN이 MKL CBWR을 따르는지 확인하지 못했다.

### 2-6. 평가 설계

**결정.**

- **작품 하나 빼기 교차 적합(4접기).** 접기 w(평가 작품)마다 학습 작품 = 나머지 셋 중 둘, 검증 작품 = 남은 하나로 둔다. 순환은 사전 고정한다: wm→검증 sherlock, q1→wm, q3→q1, sherlock→q3. 검증 작품은 온도·기준값·시드·조기 종료·small/base 선택에만 쓴다. 평가 작품은 접기마다 **한 번만** 돌린다.
- 주 결과: WM·Q1·Q3의 교차 적합 예측 60개(각 장면은 그 작품을 보지 않은 모델의 예측)를 모아 동결 열과 작품 층화 대응 bootstrap을 한다(지금 `--compare-recorded`). 셜록은 동결 열이 없어 learned만 따로 보고한다.
- 부 결과: 작품별 recall·오탐, 유형별, 담당 층별(참고), 사람 집필 카나리아, 미탐 귀속에서 **판정자 귀속 24건 중 회수 건수**와 **원장 부재 13건**(이론상 회수 불가) 분리.
- 학습 데이터 누수 차단: WM 접기에서는 WM 실제 장면(`weave_checker_corpus` = WM 평가 장면 그 자체)과 WM 기반 주입을 **모두 뺀다**. 다른 접기도 같다. 주입 기반 작품은 그 접기의 학습 작품만 쓴다.

**검정력 계산** [측정, 모의]. 동결 열 실제 예측(18/60)을 A로 둔다. B는 A가 잡은 장면 a개를 놓치고 A가 놓친 장면 b개를 잡는 가상 예측이다. 하네스 `paired_bootstrap_recall_diff`(작품 층화, 2,000회)로 구간을 냈고, 어떤 장면이 뒤집히는지를 20번 바꿔 본 중앙값이다.

| a(A만) | b(B만) | 차이 B−A | 95% 하한 중앙 [범위] | 상한 중앙 | 하한 > −0.10 ? |
|---|---|---|---|---|---|
| 3 | 3 | 0.000 | −0.067 | +0.083 | 예 |
| 6 | 6 | 0.000 | −0.100 [−0.117, −0.100] | +0.100 | 경계(아니오) |
| 9 | 9 | 0.000 | −0.117 | +0.133 | 아니오 |
| 6 | 9 | +0.050 | −0.067 | +0.167 | 예 |
| 9 | 12 | +0.050 | −0.083 | +0.183 | 예(근소) |
| 12 | 12 | 0.000 | −0.133 | +0.133 | 아니오 |
| 6 | 12 | +0.100 | −0.017 | +0.217 | 예 |

근사식으로는 하한 ≈ (b−a)/60 − 1.96·√(a+b)/60 이다. 엇갈림 a+b가 하한을 정한다.
recall이 같으면 엇갈림 ≤ 약 10건이어야 하고, +0.05면 ≤ 약 20건이어야 R2를 통과한다.
동결 열의 18건 중 15건이 WM이다. 그래서 learned가 WM에서 덜 잡고 Q1·Q3에서 더 잡는 식으로 갈리면, 평균이 같아도 엇갈림이 커져 R2를 못 넘을 수 있다.

**지시문의 "양성 54"와의 관계.** 하네스와 R2 사전 확정은 양성 60(WM·Q1·Q3 전부)을 쓴다. 54는 judge 담당 추정인데, Q1·Q3의 `expected_layer`는 라벨 스스로 "제작 측 추정"이라 적는다. 주 비교는 60, 54는 참고 칸으로 둔다.

**못 넘을 때의 주 주장.** 구간을 그대로 주 결과로 보고한다(계획서 R2 "못 넘으면 구간을 그대로"). 함께 낼 수 있는 측정된 성과는 다음과 같다.

- 판정 LLM 호출 0회
- R3 결정성
- 회차당 CPU 시간
- 판정자 귀속 미탐 중 회수 건수(Wilson 구간)
- 원장 부재가 판정기와 무관한 상한이라는 사실(Q1·Q3 40건 중 13건)

판정기가 완벽해도 Q1·Q3 recall은 27/40 이하다 [기록에서 계산].

**버린 대안.** 학습 2·검증 1·평가 1 단일 분할: 평가 양성이 20이라 하한이 −0.2 안쪽으로 오기 어렵다. 위 근사식으로 엇갈림 6이면 반폭 ≈ 0.24다. 학습 작품 수가 한 개 줄어드는 비용 대비 교차 적합이 낫다. 교차 적합은 접기마다 모델이 다르다는 점을 결과에 적는다. 서비스에 들어갈 모델은 4작품 전부(검증 하나 남김)로 따로 학습하고, 이 모델의 평가 수치는 없다고 명시한다.

**불확실한 점.** 셜록을 학습에 넣는 접기가 있어 셜록 원장(v2.3)의 조건 차이가 섞인다. 이것이 전이에 해가 되는지는 셜록을 뺀 학습 조건과의 비교로만 알 수 있다(선택 실험).

## 3. 실행 계획

### 3-1. 바꿀 파일과 함수

**`app/pipeline/pairs.py`** (학습·서비스 공용이라 여기 바꾸면 양쪽이 같이 바뀐다)

- `PAIRS_VERSION = "2"` 상수. `build_pairs` 출력 정의가 바뀌면 올린다.
- `build_pairs(..., *, max_premises=24, quotas: dict[str, int] | None = QUOTAS, excerpt_chars: int = 160, current_episode: int | None = None)`.
  - `QUOTAS = {"checker": None(전부), "ledger": 6, "knowledge": 6, "rule": 4, "past": 6, "scene": 2}`. 남는 칸은 다음 kind로 넘긴다.
  - `quotas=None`이면 지금 동작(kind 순서 + 상한). 테스트·비교용으로 남긴다.
- `_relevance(hyp_head: str, premise: str) -> float` 문자 2-gram Dice. kind 안 정렬 키는 `(-relevance, 지금 키)`.
- `_hypotheses`: 머리에 `[M화]`(group 사건의 episode, 없으면 `current_episode`)를 붙이고, 원문·근거 발췌는 `excerpt_chars`로 자른다.
- `_ledger_premises`·`_knowledge_premises`: `since` 사건의 회차로 `경과 M−N화`를 붙인다. ledger 전제에는 since 이후 같은 엔티티가 나온 corpus 사건 중 가장 이른 것 1줄(제목·요약 80자)을 붙인다. 발췌도 `excerpt_chars`로 자른다.
- 사건 단위 가설(field=None)의 ledger 전제는 대상 엔티티 전부의 필드를 모은 뒤 관련도 상위 `quotas["ledger"]`개만 남긴다.

**`app/pipeline/learned_judge.py`**

- `HFBackend.__init__(model_dir, batch_size, max_length=512, threads: int | None, padding: "bucket"|"max_length" = "bucket")`.
  - `torch.set_num_threads`, `set_num_interop_threads(1)`, `use_deterministic_algorithms(True)`를 설정한다.
  - `meta["pairs_version"] != PAIRS_VERSION`이면 `RuntimeError`.
- `HFBackend.predict`: 먼저 토큰 길이를 재고(`truncation=True, max_length`), 버킷 `(128, 256, 384, 512)` 중 맞는 것을 고른다. 버킷마다 build_pairs 순서대로 `batch_size` 묶음으로 패딩·추론한 뒤 원래 순서로 되돌린다.
- `judge_group` 반환에 `top2`(두 번째 쌍의 kind·id·p)와 `pairs_version`을 더한다.
- 결과에 환경 기록 `env`(torch 판, 스레드, MKL_CBWR, CPU 이름)를 더한다. 회차 단위라면 `weave.py` 쪽에서 한 번만 기록해도 된다.

**`app/core/config.py`**: `weave_judge_threads: int | None`, `weave_judge_max_length: int = 256`, `weave_judge_padding: str = "bucket"`, `weave_judge_device: str = "auto"`(auto|cpu|cuda), 정밀도는 모델 메타에서. `.env.example` 에도 더한다.

**`scripts/eval/export_pairs.py`**

- `--work {wm,q1,q3,sherlock}`: `judge_eval.load_context(work)`로 원장·코퍼스·레지스트리·checker 항목을 만든다. 평가와 **같은 재생**을 쓴다.
  - 지금 `pairs_for`는 `compile_ledger(episodes, knows_mode)`를 `timelines` 없이 부르고 `load_registry(base)`를 쓴다. 하네스는 `timelines=["main"]`과 `registry_live.json`을 쓴다. 학습·평가 입력이 다를 수 있으니 확인이 필요하다.
- `export_real(work)`: 근거 = WM `evidence_event_ids`, 나머지는 `evidence_event_map.json`의 matched 후보. 장면 라벨 `type`이 '설정'이면 rule 전제를 '제외'로 둔다. 근거와 같은 (엔티티, 필드)·같은 since 사건을 가리키는 쌍도 '제외'로 둔다.
- 행에 `work`, `scene_id`(= case_id), `group_id`(샘플링 단위)를 더한다.
- `--inject`는 `--work`의 기반으로 재생한다(주입 기반을 네 작품 어디서나 쓸 수 있게).
- 라벨에 `"제외"`를 더한다. `train_judge.py`는 손실에서 빼고, 보정·기준값에서도 뺀다.

**`scripts/eval/inject.py`**

- `Ctx`가 레지스트리 `registry_live.json` 형식(Q1·Q3·셜록)도 읽게 한다. 인물 3명·장소 1곳 조건은 그대로다.
- 연산자 4개 추가(어려운 음성 3 + 양성 1).
  - `state_intervening`: 부상 → 무관 사건 2~3개 → 판정. 회복 없음 = 모순, 사이에 회복 = 정상.
  - `rule_habit`: "습관·합의" 규칙과 그것을 어긴 행동 → 정상. Weave B-038 오탐 유형이다.
  - `knowledge_partial`: 비밀의 일부만 들은 인물이 그 부분만 앎 → 정상, 나머지를 앎 → 모순.
  - `state_transient`: 일시적 상태(volatility transient)가 해소된 뒤의 행동 → 정상.
- 소재 표를 작품별 문체 표본으로 늘린다. 목표는 연산자당 템플릿 ≥ 12, 행동 문장은 표현만 다른 변형 2개 이상이다. 변형은 사람이 쓴다(LLM 반사실 생성은 갈래 B가 맡는다).
- 홀드아웃은 지금처럼 연산자 1개(`knowledge_heard`)로 둔다.

**`scripts/train_judge.py`**

- `--val-work`, `--train-works`: JSONL의 `work` 필드로 분할한다. 같은 작품이 학습·검증에 동시에 들어가면 에러.
- `--loss {ce,weighted}`(기본 weighted, 빈도^−½), `--label-smoothing` (0 | 0.1).
- `--unrelated-ratio 2.0`: 에폭마다 무관 쌍을 (모순+정상)×비율로 줄인다(묶음·시드 고정). HF `Trainer`의 `compute_loss`·`get_train_dataloader`를 재정의하거나, 에폭마다 Dataset을 다시 만드는 루프로 구현한다.
- `--seeds 1 2 3`: 시드마다 학습하고, 검증 작품 장면 recall(오탐 ≤ 0.05)로 하나를 고른다. 동률이면 쌍 단위 NLL이 낮은 것. 세 시드의 지표를 모두 meta에 남긴다.
- `--epochs 6`, `--early-stop-patience 2`(검증 쌍 NLL).
- `--max-length 256`. 학습도 서비스와 같은 상한을 쓴다.
- `pick_threshold`를 `pick_scene_threshold(rows, p, target_fpr=0.05)`로 바꾼다. `scene_id`별 최댓값, 정상 장면 오탐 ≤ 목표에서 recall 최대.
- `--hyp-only`: 전제를 빈 문자열로 바꿔 같은 레시피로 학습하는 지름길 기준선(검증 지표만 보고).
- `--train-frac 0.25|0.5|1.0`: 학습 곡선.
- meta에 더할 것: `pairs_version`, `max_length`, `padding`, `scene_threshold`, `val_work`, `train_works`, 시드별 지표, 쌍 ECE, `versions`(torch·transformers·tokenizers·datasets), 토큰 길이 분위수.

**`scripts/eval/judge_eval.py`**

- `--model-dirs wm=<dir> q1=<dir> ...`: 작품별 모델 폴더(교차 적합). learned 판정기를 작품마다 따로 만든다.
- 장면별·회차 가정별 시간: `judge_group`의 `elapsed_sec`를 모아 장면 p50/p95와 합을 출력한다.
- 장면 p_scene(confidence)을 보고에 남겨 ECE·Brier·분포를 낸다.

**새 스크립트(읽기 전용)**

- `scripts/eval/pair_coverage.py`: 이 세션에서 쓴 측정을 저장소로 옮긴 것. 장면당 쌍 수·글자 수, 정답 근거 포함(상한·할당량별), kind 분포를 낸다. pairs 개정 뒤 §2-3 목표(≥ 66/75)를 확인한다.
- `scripts/eval/judge_latency.py`: 합성 회차(사건 30개·과거 300건, 계획서 기준) 하나를 만들어 learned 판정 시간을 잰다. 워커와 같은 환경 변수·스레드로 돌린다.

**테스트(`tests/test_learned_judge.py`에 더함)**

- 할당량 결정성(같은 입력 → 같은 순서)
- `quotas=None`이면 지금 출력과 같음
- pairs_version 불일치 시 로드 에러
- 버킷 패딩 순서 복원(가짜 백엔드로 순서만 검사)

### 3-3. 첫 실험에서 볼 지표와 중단 기준

순서대로 본다. 앞 관문을 못 넘으면 뒤로 가지 않는다.

| 관문 | 지표 | 통과 기준 | 못 넘으면 |
|---|---|---|---|
| G0 쌍 | `pair_coverage.py` 근거 포함 | ≥ 66/75 (할당량 합 24) | 관련도 함수 수정(학습 작품에서만 판단) |
| G0 길이 | 토큰 p95 | ≤ 256 | 발췌 길이 축소 |
| G1 지연 | `judge_latency.py` 회차(30사건) 시간, 워커 GPU, base·large fp16 (CPU 대체 경로는 small·fp32 따로) | ≤ 60초 | GPU: 할당량 합 16 → base. CPU 경로: 할당량 16 → int8(별도 보정) → 버킷 128 |
| G2 결정성 | 두 번 실행·재기동 비트 동일 | 동일 | 고정 항목 재점검. 안 되면 배치 1 |
| G3 전이 | 영 학습 기준선 검증 장면 recall(오탐 ≤ 0.05) | 기록만 | — |
| G4 지름길 | 검증 작품 쌍 단위 PR-AUC(모순 대 나머지): 전체 모델 − hyp-only | ≥ 0.10 | 가설 문체 단서 점검, 주입 템플릿 다양화. 이 상태로 평가하지 않는다 |
| G5 안정성 | 시드 3개의 검증 장면 recall 범위 | ≤ 0.20 | 데이터 부족으로 보고 학습 곡선 확인, 갈래 B 확대 판단 |
| G6 검증 성능 | 접기별 검증 작품 장면 recall(오탐 ≤ 0.05)과 **같은 작품의 동결 열 recall** 비교(검증 작품의 동결 열 값은 이미 공개된 기록이라 누수 아님) | 4접기 중 3접기 이상에서 동결 열 − 0.10 이상 | 평가 작품은 돌리지 않는다. 학습 곡선·오류 분석 후 다음 판 |
| G7 평가 | 접기별 평가 작품 1회 → 60개 모아 대응 bootstrap | R2 하한 > −0.10 | 구간 그대로 보고(§2-6) |

평가 작품 결과를 본 뒤에는 쌍 정식화·할당량·기준값 규칙·모델 선택 규칙을 바꾸지 않는다. 바꾸면 새 판으로 새 측정을 하고 옛 결과와 나란히 적는다(Weave 열 분리 원칙).
