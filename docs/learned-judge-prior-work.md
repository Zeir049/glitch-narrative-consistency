# 장편 서사 모순 검출 — 선행 연구 조사와 이 프로젝트 적용 판단

2026-11-06 설계 세션이 검색·확인해 썼고, 같은 날 검증 세션의 대조([`learned-judge-design-review.md`](learned-judge-design-review.md))로
고쳤다(v2). 목적: judge를 학습하기 전에 **같은 과제(장편 서사의 설정·연속성 모순)를 겨냥한 판정기·데이터셋**이 무엇이 있는지 보고,
이 프로젝트의 설계(원장 + 규칙 checker + 쌍 분류 judge)에 무엇을 가져오면 좋은 결과가 나올지 판단한다.
수치는 각 논문이 보고한 값이고 **지표·조건이 우리와 다르므로 비교는 방향만 본다.** 열람일은 전부 2026-11-06.

## 2. 판단 — 우리 설계에 무엇을 가져올 것인가

### 2-1. 구조는 맞다. 바꿀 것은 데이터 규모다 — 단, 양성의 공급원을 분명히 한다

FactTrack(사실 원장 + 쌍 NLI)과 ConStory-Checker(추출 → 쌍 → 판정)가 우리와 같은 구조로 가장 좋은 결과를 냈고, 책 전체를 한 번에
판정하는 방식(NoCha, FlawedFictionsLong)은 최신 LLM도 길이가 늘면 무너진다. 결정적 원장 + 쌍 판정은 방어할 수 있는 선택이다.

성공한 소형 판정기는 수천~수만 쌍 라벨을 썼다(MiniCheck 14K~35K, FactTrack 18.7K). 우리는 모순 쌍 168개다. 그래서
LLM으로 만든 데이터를 **1단계**로 올린다. 다만 검증 기록이 짚은 반론 여섯을 설계에 넣는다.

**생성기는 유료 API가 아니라 로컬 모델이다(사용자 결정 2026-11-07 — 유료 키는 검증 단계 전용).** 이 PC의 RTX 3060에서 OpenAI 호환 서버를
띄워 어댑터의 LLM 경로를 그대로 쓴다(설계안 §0-5). 품질이 낮은 만큼 자기일관성 필터·사람 검토가 더 중요하고, 첫 실험은 외부 데이터 없이 돌린다.

| 갈래 | 방법 (출처) | 목표 규모 | 역할 | 품질 관리 |
|---|---|---|---|---|
| A. 쌍 라벨링 | FactTrack식. **각 접기의 학습 작품** 확정 회차에서 `build_pairs`로 쌍을 뽑고(관련도 필터 통과분), LLM에 모순/정상/무관/판단불가 라벨 | 1~2만 쌍 | 원작 원장은 내부적으로 거의 일관하므로 **참 양성은 드물다**. A는 주로 정상·무관(관련도 구분)과 소수 양성을 공급 | 이중 라벨(모델 2개 또는 2회), 불일치·판단불가는 '제외'. **제외율을 보고**(어려운 쌍을 버려 쉬운 분포로 기우는 위험). 200건 사람 표본 검수 |
| B. 반사실 회차 | FlawedFictionsMaker식. 앞 회차의 "중간 중요도" 사실 하나를 부정해 **뒷 회차(또는 다음 회차 장면)를 다시 쓴다**(앞 회차 원본 유지). 한국어, 학습 작품 2~3편 | 모순 200~300건 + 같은 사실을 지키는 **정상 장면** 짝 | **참 양성의 주 공급원** | LLM 자기일관성(5회 중 4회) → 사람 검증(채택 70% 예상, 건당 검증자 수·시간을 계획에 적는다). **음성도 재작성본**(FlawedFictions `cf_negs`)을 두어 문체 단서를 없앤다 |

- **누수 규칙(고정)**: 평가 작품의 회차·장면은 어느 접기에서도 라벨링·생성에 쓰지 않는다. B의 산출물은 학습 전용이다. 원문 주입 **평가**셋을 원하면 평가 전용 작품으로 따로 만든다.
- **추출 의존**: B의 장면은 Weave 추출(LLM)을 거쳐야 쌍이 된다. 추출 비용과 추출 잡음(`docs/EVAL.md` 반복 추출 일치도: 값 J 0.01)이 라벨에 섞인다. 추출 녹화(`WEAVE_LLM_RECORD`)로 재실행 비용을 없앤다.
- **비용**: 로컬 모델이라 금전 비용은 없고 시간이 비용이다. 쌍 1~2만 × 라벨 2회 × 건당 수 초 ≈ 수십 시간(3060, 7~8B 4비트 기준 [추정]); 반사실 300건 × (생성 + 검사 5회) ≈ 수 시간. 유료 API 기준 추정(E 도구 README)은 참고값으로만 남긴다.
- **지름길 감시**: LLM 라벨·생성 데이터는 가설만 보는 편향의 원천이 될 수 있다(Proebsting & Poliak 2024). 설계안 G4(가설만 보는 기준선과의 PR-AUC 차이 ≥ 0.10)를 통과 관문으로 둔다. LLM 데이터 없는 조건(구조 주입 + 실제 장면)을 대조 조건으로 같이 학습해 득실을 잰다.

구조 주입 `inject.py`는 대조 묶음·어려운 음성 보조로 남긴다. MiniCheck의 부분집합 대조셋은 `state_contrast` 연산자와 같은 발상이니 확장한다.

### 2-2. 모델은 base부터, large로 상한을 재고, small은 CPU 대체 경로로만

MiniCheck·FactTrack은 large 인코더(또는 770M 인코더-디코더)를 썼고, 소형 인코더가 이 과제에서 되었다는 보고는 찾지 못했다.
KLUE-NLI ACC는 small 79.33 / base 84.83 / large 89.17(KLUE README)이다. 순서: `klue/roberta-base`로 먼저 학습해 성능이 나오는지 보고,
로컬 3060으로 `-large` 상한을 잰 뒤 정확도로 고른다. small은 GPU 없는 배포 환경의 대체 경로다.
(FlawedFictions의 "8B는 우연 수준"은 영 학습 디코더 LLM 결과라 인코더 크기 선택의 근거가 아니다.)

### 2-3. 목표 수치 — 같은 설정의 선행 수치는 없다

| 조건 | recall | precision 계열 | 지표 단위 |
|---|---|---|---|
| ConStory-Checker (o4-mini) | 0.55 | precision 0.88 | 합성 이야기의 **주입 오류 단위** |
| FactTrack (DeBERTa-large, GPT-4 라벨) | 0.60 | precision 0.60 | **쌍 단위**, 정답 GPT-4 |
| 우리 제품 동결 열 (nemotron:free, k=3) | 0.30 | 정상 장면 오탐 0.05 | **장면 단위** |

세 줄의 지표가 다르므로 "문헌 수준"이라는 말은 쓰지 않는다. 쓰는 말은 둘이다.
**발표 주장은 R2**(동결 열 0.30 대비 비열등, 하한 > −10%p). **recall 0.5·정상 장면 오탐 ≤ 0.05는 내부 목표**다.
맥락 문장은 "서사 범위에서 최고 LLM 파이프라인의 recall은 0.55(ConStory)~0.63(FactTrack on ContraDoc)"까지만.

### 2-4. 평가 지표 — 하나는 조건부, 하나는 진단용

- **근거 적중**(FlawedFictions CEEval 발상): 검출했고 `evidence_event_ids`가 정답 근거와 겹칠 때만 정답. **지금은 WM에만** 근거 사건 ID 라벨이 있다.
  Q1·Q3·셜록은 `evidence_event_map.json`의 문자열 대조 후보(matched/ambiguous/unmatched, "확정 전 사람 확인 필수")라 사람 확정 뒤에만 쓸 수 있다.
  학습 judge의 `evidence_event_ids`는 최고 쌍 전제 ID 하나라 문장 위치 지표와 단위도 다르다.
- **쌍 정확도**(NoCha 발상): 대조 묶음의 모순·정상이 둘 다 맞아야 정답. 4코퍼스 실제 라벨에는 대조 쌍 필드가 없으므로
  **학습·검증(구조 주입·갈래 B) 진단 지표**이지 평가 지표가 아니다.
- recall은 정상 장면 오탐 ≤ 0.05에서 보고한다(설계안 §2-4).

### 2-5. 분류표를 빌린다

ConStory의 5범주 19소분류를 우리 유형에 대응시켜 **주입 연산자 목록과 보고 범주**로 쓴다(진단셋은 비공개라 데이터는 못 가져온다).

| ConStory 범주 (소분류 수) | 우리가 다루는 것 | 다루지 않는 것(명시) |
|---|---|---|
| Characterization (4): 기억·지식·능력 변동·잊힌 능력 | 지식(knows/not_knows), 능력(ability), 신체(body_status) | 성격·동기 |
| World-building & Setting (3): 핵심 규칙·사회 규범·지리 | 세계관 규칙, 위치 | 사회 규범 |
| Factual & Detail (3): 외모·명칭·수량 | 수량(규칙·상태 값), 명칭(엔티티 해석) | 외모(추출 스키마에 없음) |
| Timeline & Plot Logic (6): 절대 시각·기간·동시성·원인 없는 결과·인과·**방치된 플롯 요소** | 부분(since 회차·경과) | 인과·동시성·방치된 플롯(시간선 엔진 과제) |
| Narrative & Style (3): 시점·어조·문체 | 없음 | 전부 |

### 2-6. 쌍 선택은 설계안 방향이 맞다

FactTrack은 NLI 전에 검색 유사도 0.5로 쌍을 거르고, 두 시점 모두에서 모순일 때만 표시해 오탐을 줄였다. 설계안의
"kind별 할당량 + 관련도 정렬"과 "경과 회차·since 이후 사건 표기"는 같은 방향이다. 우리는 결정성 때문에 임베딩 대신
문자 2-gram 관련도를 쓴다. 근거 포함률 목표(상한 24에서 ≥ 66/75; 근거 후보는 matched·ambiguous 전부로 센 값)는 그대로.

### 2-7. 작가 검수 주장에 쓸 수 있는 근거 (조건부)

ConStory에서 전문 웹소설 작가 두 명의 오류 발견 F1은 표 6 기준 0.229(본문은 0.281, 논문 내 불일치), 파이프라인은 0.678이었다.
"작가 검수를 선택으로"의 근거로 쓸 수 있으나, 그 작가들은 **남이 쓴 LLM 합성 이야기 200편**(길이 미기재)을 읽은 것이라
자기 작품을 아는 작가와는 조건이 다르다고 반드시 적는다.

## 3. 바뀌는 실행 순서

1. **데이터 (로컬 LLM, 유료 키 금지)**: 로컬 OpenAI 호환 서버 준비 → 갈래 B 반사실 회차(참 양성) → 갈래 A 쌍 라벨링(로컬 모델 2개 이중 라벨) → 사람 표본 검수 200 + 반사실 검증. 영어 쌍 번역은 학습 곡선이 부족을 가리킬 때. 누수 규칙 준수. 평가 4코퍼스는 건드리지 않는다.
2. **쌍 생성기 개정**(설계안 §3-1): 할당량·관련도·경과 회차. `pair_coverage.py`로 근거 포함률 확인.
3. **학습**: base → large(상한) → 필요하면 small(CPU 경로). 설계안의 가중 CE·묶음 샘플링·장면 단위 기준값·G4 지름길 관문은 유지.
4. **평가**: 하네스(장면 단위, 오탐 ≤ 0.05에서 recall) + 쌍 정확도(진단) + 근거 적중(WM, 확정 후 확대). R2는 동결 열 대비 bootstrap.
5. **지연**: 모델이 정해진 뒤 GPU 실측(fp16) → CPU 대체 경로는 int8·할당량으로 맞춘다.
