# 조사 세션 지시문 — 학습 judge를 이 프로젝트에서 어떻게 설계·학습할 것인가

> 이 파일을 통째로 새 세션의 첫 메시지로 붙여 넣는다. 조사·설계 전용이며 **코드를 고치지 않는다.**
> 결과물은 `docs/learned-judge-training-design.md` 하나다.

## 너의 일

장편 서사의 설정 모순을 잡는 백엔드 Glitch(저장소 루트 = 이 폴더, `CLAUDE.md` 먼저)에서, 판정 단계의 LLM을
**학습 모델(judge)** 로 바꾸는 작업이 진행 중이다. 코드 연결은 끝났고(가짜 백엔드로 끝까지 돈다) **실제 모델 학습은 아직**이다.
너는 (1) 관련 기법·모델을 조사하고, (2) 이 프로젝트의 데이터·제약에 맞는 **학습 설계안**을 결정하고, (3) 그 설계를
지금 있는 스크립트로 실행하려면 무엇을 바꿔야 하는지 구체적으로 적는다. 숫자를 낼 수 있는 것은 숫자로, 추정은 추정이라고 쓴다.

## 먼저 읽을 것 (순서대로)

1. `docs/learned-judge-plan.md` — 요구 R1~R3, 사전 확정 기준(주 기준선 = 제품 동결 열 Recall 0.30, δ 10%p, 작품 단위 분할, CPU 60초/회차)
2. `docs/learned-judge-decisions.md` — 왜 cross-encoder·NLI 3클래스인지, 버린 대안, 확인된 사실
3. `app/pipeline/pairs.py` — (가설, 전제) 쌍 생성기. 가설 = assumed_states 항목 + 요약 + 원문 발췌, 사건 단위 가설 하나 추가.
   전제 kind 순서 checker→ledger→rule→knowledge→scene→past, 가설당 상한 32. **학습 내보내기와 서비스 추론이 같은 함수**
4. `app/pipeline/learned_judge.py` — `LearnedJudge`: 쌍별 [모순, 정상·관련, 무관] 확률 → 모순 확률 최대 쌍 하나가 대표, threshold 이상이면 양성.
   HF 백엔드는 `padding="max_length"`·`max_length=512`·배치 고정(결정성)
5. `scripts/eval/inject.py`, `scripts/eval/export_pairs.py`, `scripts/train_judge.py` — 주입 생성기(연산자 8개), JSONL 내보내기, 학습 스크립트
   (KLUE-NLI 기초 학습 선택 → 본 학습 → 온도 보정 → 기준값 선택 → judge_meta.json). **클래스 가중치·샘플링 없음**
6. `scripts/eval/judge_eval.py`, `docs/EVAL.md` — 평가 하네스(recorded/learned/llm 모드, 작품별·유형별, 대응 bootstrap)
7. `app/pipeline/weave_core/checker.py` 머리말, `judge.py` 머리말 — 규칙 checker가 무엇을 잡고 judge가 무엇을 맡는지
8. Weave 원본 저장소 `%USERPROFILE%\Downloads\event_sourcing`(읽기 전용): `handoff/final_report.md`, `handoff/longitudinal_report.md`
   (동결 열 측정, 미탐 귀속), `handoff/PHASE4_평가재설계.md`(추출이 정답을 조준하는 문제), `handoff/track1_report.md`(k=3 프로토콜)

## 이미 확인된 사실 (다시 조사하지 말 것)

- 정답 코퍼스 4작품 165장면: WM 30(모순 20 / 정상 10), Q1 금호탕·Q3 돔 C-4·셜록 각 45(모순 20 = 상태 8·설정 6·지식 6 / 정상 25).
  모순 80건 중 judge 담당은 약 54(WM 16 + 나머지는 라벨 `expected_layer`가 "제작 측 추정"이라 참고용). `tests/eval/weave_judge_corpus/`.
- 제품 조건 LLM judge(nemotron:free, k=3)의 동결 열: Recall 0.30 (18/60), 오탐 0.05. 미탐 37건 = 원장 부재 13(추출이 놓침) / 판정자 24.
  이 저장소 하네스가 이 값을 재현한다. 개선 열(rnc 패킷 + Claude Sonnet) 0.767은 제품 경로 미연결이라 참조 상한일 뿐.
- 지금 WM 하나로 내보낸 학습 쌍: 모순 168 / 정상 245 / 무관 4,147 (주입 70 + 실제 장면 98 모순). **모순이 4%**.
  "정답이 명시되지 않은 쌍 = 무관"은 근사라 라벨 잡음이 있다.
- 학습 환경 Colab T4(16GB, fp16), 서비스 추론은 워커 CPU(GPU 없음). 결정성 필수(같은 입력 → 같은 결과).
- 한국어. 쌍 입력은 512토큰. 가설·전제 모두 한국어 자유 서술 + 구조 필드(엔티티.필드 = 값, since 사건, 발췌).
- 원본 WM 코퍼스 추출은 심어 놓은 모순을 조준한 것이라, 구조 주입으로 만든 평가셋은 쓰지 않는다. 평가는 실제 4코퍼스(작품 단위 분할).
- 가짜 백엔드(반의어 소사전)는 4작품에서 recall 0.89·오탐 0.94 — 연결 확인용이지 성능 아님.
- 라이선스: KLUE 데이터·`klue/roberta-*`는 CC BY-SA 4.0. 상업 서비스 가정은 아니지만 결과물에 라이선스 표를 넣는다.

## 답해야 할 질문

1. **모델 선택.** `klue/roberta-base` vs `-large` vs 한국어 NLI로 이미 미세조정된 공개 체크포인트(있으면 이름·라이선스·성능) vs
   다국어 reranker(`BAAI/bge-reranker-v2-m3` 등) vs 소형 LLM(QLoRA). 기준: 한국어 NLI 성능, 512토큰 CPU 추론 지연(쌍당·배치 32당),
   T4에서 학습 가능 여부, 결정성, 라이선스. 회차당 쌍 수 추정(장면 6개 × 가설 ~5 × 전제 32 ≈ 1,000쌍)으로 **CPU 60초 상한에 드는지** 계산.
2. **적은 양성으로 배우는 법.** 모순 168쌍(실제 98)은 너무 적다. 다음을 근거와 함께 판단: KLUE-NLI 사전 학습의 전이가 얼마나 되나
   (모순 ≈ contradiction?), 클래스 불균형 처리(가중 손실·오버샘플링·focal, 무엇을 쓸지), 대조 묶음(같은 전제로 모순·정상·무관)의 효과,
   어려운 음성(회복 사건 끼움, 규칙 예외, 들은 장면, 점진 변화)을 어떻게 더 만들지, LLM 오프라인 증강(원문 문체로 가설 생성)의 득실과
   지름길 학습 위험, 필요한 양성 수의 대략적 하한(비슷한 설정의 문헌 수치).
3. **쌍 정식화가 맞나.** 3클래스 NLI vs 이진(모순/아님) + 관련도 별도, 패킷 집계(최댓값 vs noisy-OR vs 학습된 집계기),
   전제 상한 32와 kind 순서가 recall을 깎지 않나, 사건 단위 가설의 효용, 원문 발췌 길이. 시간 관계("4화에 다쳤다 → 6화에 손을 쓴다"는
   회복이 있으면 정상)를 쌍 분류가 다룰 수 있나, 못 하면 어떤 입력(since 회차·사이 사건 요약)을 붙여야 하나.
4. **보정과 기준값.** 온도 보정 + F1 최대 기준값이 적절한가, 작품별 보정 차이(ECE)를 어떻게 보고할지, 애매한 구간 폭.
5. **결정성.** CPU torch에서 같은 입력·같은 배치면 비트 동일한가, 스레드 수·MKL·padding 설정 등 고정해야 할 것 목록.
6. **평가 설계.** 4작품 중 학습 2·검증 1·평가 1 vs 작품 하나 빼기 교차. 양성 54건으로 δ=10%p 비열등 bootstrap 하한이
   나올 수 있는지(기대 구간 폭 계산). 안 되면 무엇을 주 주장으로 할지.
7. **실행 계획.** 위 결정을 `scripts/train_judge.py`·`export_pairs.py`·`inject.py`에 반영하려면 바꿀 곳(함수·인자 수준), Colab 셀 순서,
   예상 학습 시간, 산출물(모델 폴더·해시·judge_meta.json), 첫 실험에서 볼 지표와 중단 기준.

## 조사 방법

- 웹에서 최신 자료를 확인한다: 한국어 NLI 벤치마크(KLUE-NLI, KorNLI), 공개 한국어 cross-encoder/NLI 체크포인트, 소수 양성 NLI 미세조정,
  cross-encoder vs reranker CPU 지연, 서사 일관성·캐릭터 일관성 검출 논문(장편 소설 모순 검출, long-form consistency), 결정적 CPU 추론.
  출처는 URL과 날짜를 적는다. 모델 카드의 라이선스·입력 길이·언어를 반드시 확인한다.
- 추정 계산은 식을 보인다(예: 쌍 수 × 쌍당 지연).
- 코드는 읽기만 한다. 실행이 필요하면 `.venv` 파이썬으로 읽기 전용 스크립트만(예: 쌍 수 세기). transformers는 설치하지 않는다.

5. 라이선스 표
6. 참고 자료(URL·날짜)
